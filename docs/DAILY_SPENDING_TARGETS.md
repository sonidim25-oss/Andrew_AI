# Daily spending targets are advisory

Owner policy: Andrew may choose whether to keep daily spending within the suggested target or exceed it for work he considers worthwhile. Current daily totals and targets remain visible; crossing a daily dollar target does not by itself reject a reasoning request, prevent an autonomous session, or reject/cancel an authorized media job.

Reasoning uses the configured `ANDREW_DAILY_TARGET_USD` (normally $0.30) as guidance. `check_budget`, `/budget`, and the gateway's current budget context distinguish it from the monthly limit. The previous calendar-day accrued allowance no longer constrains admission: ordinary work can use the remaining monthly budget after the protected reserve, including on the first day of a month. Settled charges and uncertain reservations still count against the monthly amount.

Voice and image daily dollar targets remain configurable through `ANDREW_MEDIA_DAILY_PER_KIND_USD` (normally $0.20 per kind). The existing `MediaPolicy.daily_usd` configuration field now describes a target rather than a cap. `media.status` exposes `daily_target_usd` and `daily_target_enforced: false` instead of `daily_cap_usd`. Submission and queued-job revalidation enforce monthly and per-job budgets only. Monthly reservations continue to be checked together, including after a configuration change.

Monthly reasoning limits and reserve, separate monthly media caps, per-job media caps, owner authorization, daily media job-count quotas and lifecycle controls continue to apply. The standing prompt and trusted voice/image documents communicate this distinction, while current tool results supply the actual configured amounts and usage. No historical usage, conversation or memory records are rewritten by this change.

Verification: the final core suite passed 397 tests with two optional skips. New regressions cover first-day spending above the target, full monthly availability, month changes, retained uncertainty reservations, autonomous session admission, a gateway provider dispatch followed by monthly-budget refusal, media admission/claim above a target, and an existing queue surviving a lowered daily target. Existing queue tests still exercise monthly and per-job revalidation. All provider behavior is isolated and synthetic; no live provider charge or production wake is part of verification. All 90 installer/protocol tests passed with the pinned isolated Letta backend. Production rollout remains separate.

Deployment requires the updated controller modules, trusted voice/image documents, loader and installer manifest together. The reviewed installer includes `budget.py`; changing only the displayed daily target or a configuration value would leave the old accrued-allowance gate in place. Production installation requires the server's sudo credentials and remains separate from source verification.
